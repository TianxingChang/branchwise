The unit of AI-assisted work stopped being a session. It became a branch of exploration.

Every shipping competitor draws parallel agents as a flat list. A list is lossless only while the work is independent. The moment branch B was cut from branch A because A has to land first, the list throws away the one fact that decides what you do next. branchwise draws that fact — and git already records it, in the reflog, so the map can be reconstructed from evidence instead of maintained by hand.

The bet

Past ~5 concurrent worktrees the load stops being “which agent is running” and becomes “what depends on what, and in what order does this land.”

The counter-bet

Most trees are flat — N branches off main. A fan of eight nodes off one root is a list, drawn with ten times the pixels. Measure depth before building on it.

The user

Not the solo vibe coder — they churn to a free, funded incumbent. The staff engineer with 5–15 live worktrees who genuinely stacks. Only there is the tree load-bearing.

The one-sentence v1.0

A stranger downloads it, opens their private repo, branches, runs an agent, lands it, quits — and the repo is exactly as they'd expect, with nothing extra in it and nothing sent anywhere.

How to use this document. The map is the dependency graph of every remaining increment — click a node to jump to its card. Each card carries a demo sentence, acceptance criteria, the traps to watch, and a prompt seed you can paste straight into a coding session. Decisions exists so settled questions stay settled and open ones stay visible. Measured holds facts verified against real git, a real Claude CLI and a real APFS volume — trust those over memory, including your own.

Dashed edges are advisory: doing them out of order costs rework, not correctness. Colour means state only, never category — the same rule this atlas prescribes for the app's own node cards. Timeline

~10 weeks solo, 3–5 increments per week

Weeks are a shape, not a promise. Two things are worth reading literally: the release track starts in week one because Apple enrolment has an unbounded external wait, and the agent runtime cannot start before the streaming spike has an answer. Everything else can slip right without breaking the plan.

Increments

one session each · one demo sentence each

An increment is one session: roughly 200–600 changed lines, one demo you can perform, one section of the spec. If you can't write the demo sentence before starting, it isn't scoped yet — split it. Every card ends with a prompt seed; paste it, then hold the result to the acceptance list.

Decisions

so settled things stay settled

The point of writing these down is that an agent starting a fresh session has no memory of why. settled means do not re-litigate without new evidence. open means it blocks work — decide it before the increment that depends on it. reverse means the current code embodies a choice that should change, and the cost grows every week it doesn't.

Landscape

The category's price is zero and it was set by better-funded people. Crystal was deprecated, Terragon shut down and Vibe Kanban's company folded, all in the first half of 2026. That is the context for every monetisation thought: open source, bring-your-own subscription, never proxy credentials. Across every roundup checked, no shipping tool uses a canvas or graph metaphor — which is either an unoccupied position or a well-explored dead end. Find out cheaply.

Standing rules

the loop that keeps this shippable

Written for one person working with coding agents. Every item is either a command with an exit code or a step so concrete an agent cannot claim it without doing it. “Looks right” is not on the list.

Gate 0 · machine-checkable

  • npm run typecheck — add this script first; it does not exist yet.
  • npm run check — zero errors, not “fewer errors”.
  • npm run test — all vitest projects.
  • npm run package — typecheck catches type errors; only a build catches a deleted module. Both were needed the one time this failed.
  • Paste the real output into the session summary. An agent asserting “tests pass” without output is not evidence.
  • Review git status --short. A D on a source file means grep for importers before the session ends.

Gate 1 · tests

  • New pure logic → a unit test. New git / fs / process / IPC logic → an integration test against real git, real fs, real child processes. Mocking git tests your belief about git.
  • At least one new test must fail when the change is reverted. Verify by actually reverting. This is the only defence against tests that assert nothing.
  • No test deleted or skipped to make the suite pass. If one is genuinely obsolete, say which and why in a sentence.
  • No fixed sleep in a new test — poll a condition with a timeout.

Gate 2 · the human's job

  • Launch the app. Walk the increment's demo script — which the plan named before work started.
  • Re-read the two known landmines: no memo() (React Compiler is on, and Biome panics on it), and every new Zustand selector returns a stable reference or useSyncExternalStore loops forever.
  • Touched src/ipc/? Full restart. The main process is not hot-reloaded.
  • Touched git? Run it against a real repo with real history and a dirty working tree — not only a fixture.

Gate 3 · truth maintenance

  • README reflects reality. If an increment invalidates a README claim, the increment isn't done.
  • Where the implementation diverged from the spec, update the spec with a one-line why. A spec that drifts silently is worse than none.
  • Any decision reversed mid-increment gets a line in Decisions.
  • User-visible change → a line in CHANGELOG.md.

Gate 4 · stop the line

  • main must always typecheck, lint, test and package. If an increment can't reach that state it does not merge — branch it or revert it. There is no “I'll fix the types after”.
  • Commit at every green point. Tag last-known-good before anything structural.
  • Never begin a session on a dirty tree. Agents compound existing breakage with new breakage and the diff becomes unreadable.
  • Never delete a module and its consumers in separate sessions. Same increment, or leave a re-export shim.
  • Review in a different session than the one that wrote the code. An agent that writes both code and test satisfies both with the same misunderstanding.

Gate 5 · privacy, non-negotiable

  • No repository content leaves the machine. Not paths, names, diffs, SHAs, file names. Branch names are frequently the product secret.
  • Nothing written inside the user's repo except .branchwise/, small, human-readable, self-ignoring.
  • Agent environments carry API keys. Never log process.env, never include it in diagnostics, never crash-report it.
  • Any diagnostic export is previewable before it moves, redacted by default, copied to the clipboard — never uploaded.
